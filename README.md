# Лаба 1 — Коробка байтів

Взяв скелет ember і дописав читання та запис байта, ASCII-колонку,
вивід байта у чотирьох форматах і команду `inc`.
Робив у GitHub Codespaces на Linux, компілятор GCC 13.3.0.

## Як запустити

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
    cmake --build build
    ./build/ember

Збирав на C++17 з `-Wall -Wextra -Werror`. У Debug увімкнені ASan і UBSan.

Команди: `dump`, `get <addr>`, `set <addr> <value>`,
`inc <addr>`, `help`, `quit`. Адреси — від 0 до 4095, значення — від 0 до 255.

## Розміри типів

Перевірив через `sizeof`:

| Тип | Байтів |
|---|---|
| char | 1 |
| uint8_t | 1 |
| uint16_t | 2 |
| int | 4 |
| unsigned | 4 |
| float | 4 |
| double | 8 |


Для комірки використовується `std::uint8_t`: це один байт, який зберігає
0–255. `int` у моєму середовищі займає чотири байти.

## Перевірка пам’яті

Після нового запуску виконав `dump`. Пам’ять заповнена нулями завдяки
`Byte data[MEM_SIZE]{}`. Ось вітання і перші три рядки:

```text
ember 0.1 - 4096 bytes of memory you can see. Type `help`.
ember> 0000  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

Записав 255, перевірив через `get 0`, виконав `inc 0` і знову `get 0`.
Отримав 0: при перетворенні числа 256 у байт воно загортається за модулем 256.
Команда `inc 5000` дала помилку, бо такої адреси немає.

Потім виконав `set 0 65`, `get 0`, `set 1 66`, `set 2 0` та `dump`:

```text
ember 0.1 - 4096 bytes of memory you can see. Type `help`.
ember> ember> 255  0xff  0b11111111  '.'
ember> ember> 0  0x00  0b00000000  '.'
ember> address is outside 0..4095
ember> ember> 65  0x41  0b01000001  'A'
ember> ember> ember> 0000  41 42 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |AB..............|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

65, 0x41, 0b01000001 та A — той самий байт у різних форматах.
У дампі видно AB. Нуль після букв завершує C-рядок, а в ASCII-колонці
показується крапкою. Кілька `ember>` підряд у файлі з’явилися через подачу
команд через стандартний ввід.

## Переповнення int

В окремій програмі взяв найбільше значення `int` і додав 1.
Зібрав із `-fsanitize=address,undefined -fno-sanitize-recover=undefined`.

```text
Before: 2147483647
/tmp/lab01-overflow.cpp:7:11: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
```

UBSan повідомив про переповнення і зупинив програму.
Для знакового `int` це невизначена поведінка. Очікувати загортання,
як у беззнакового байта, не можна.

## Дроби

Порівняв `0.1 + 0.2` з `0.3` і надрукував 17 значущих цифр:

```text
0.1 + 0.2 = 0.30000000000000004
0.3       = 0.29999999999999999
equal: false
```

Отримав `false`. Ці дроби зберігаються в `double` приблизно, бо не мають
точного скінченного запису у двійковій системі. У виводі видно невелику
різницю, а `==` перевіряє точну рівність.

## Що буде без {}

Зробив копію проєкту, прибрав `{}` з масиву і запустив `dump`.
У `main.cpp` об’єкт створювався як `Memory mem;`.

```text
ember 0.1 - 4096 bytes of memory you can see. Type `help`.
ember> 0000  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

На початку дампа все одно побачив нулі. Але без ініціалізації вони
не гарантовані, а читання такої пам’яті у C++17 — невизначена поведінка.
ASan і UBSan не зобов’язані її помітити. В основному проєкті `{}` залишив.

## Лаба 2 — біти й маленький CPU

У цій лабі додав процесор з регістрами A, B, PC і прапорцями Z, N, C. Команди вводяться в тому ж REPL.

Працюють такі інструкції: HALT, NOP, ADD, SUB, AND, OR, XOR, NOT, SHL, SHR, INC, DEC. Опкод ділю на групу та номер через (op >> 4) & 0x0F.

### Коротка перевірка

200 + 100 у байті дає 44, бо 300 не вміщується в 8 біт. Після ADD маємо A=44 і C=1.

    reg a 200
    reg b 100
    set 0 16
    step
    regs
    PC=1 A=44 B=100 Z=0 N=0 C=1

Ще приклад зі зсувом: якщо в A лежить 128, команда SHL дасть A=0, Z=1, C=1: старший біт вийшов назовні.

Трасування програми з трьох інструкцій:

    set 0 16   # ADD
    set 1 24   # INC
    set 2 0    # HALT
    reg a 200
    reg b 100
    step       # A=44, C=1
    step       # A=45, C лишається 1
    step       # CPU halted
